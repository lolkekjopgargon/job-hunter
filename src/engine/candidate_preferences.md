# candidate_preferences.md

# Purpose
This file defines what kinds of jobs Pavel wants the job-search agent to prioritize, deprioritize, or avoid.

The agent should use this file together with:
- candidate_facts.md
- portfolio_index.md
- application_rules.md (if present)

Do not treat preferences as candidate experience.

## 1.1. 3D & Character Art Preference

### Preferred 3D Roles:
- 3D Generalist
- Unreal Engine Artist / Technical Artist (Scene assembly, lighting, camera animation)
- Previs Artist
- 3D Scan Cleanup / Retopology / Real-time Character Preparation

### NOT Preferred / Major Gap:
- Character Sculptor from scratch
- Senior Character Artist (focused on high-poly sculpting and anatomy from scratch)

Rule: Pavel does NOT sculpt characters from scratch. His character experience is strictly working with 3D scan data, cleaning up scans, retopology, and preparing existing character assets for Unreal/real-time engines. If sculpting from scratch is the primary role, mark as `NOT MATCHED / MAJOR GAP: Character sculpting from scratch`.

## 7. Seniority

Good targets:
- Junior+ where responsibilities are meaningful
- Middle
- Strong Middle
- Specialist roles matching Pavel's actual experience

Use caution with:
- Senior
- Lead
- Head
- Principal

Only surface higher-seniority roles if the actual requirements overlap strongly and do not require unverified leadership history.

## 8. Vacancy quality filter

Prefer vacancies that:
- describe concrete responsibilities;
- mention actual tools/workflows;
- have a clear product/project;
- value cross-disciplinary experience;
- allow portfolio review;
- have meaningful creative ownership;
- are not obviously mass-hiring spam.

Flag as suspicious or low-priority:
- vague "do everything" jobs;
- impossible experience requirements for very new tools;
- excessive unpaid test tasks;
- large take-home assignments without compensation;
- job descriptions combining many unrelated full-time roles without clear scope.

Do not automatically reject; mark for Pavel.

---

## 9. Application strategy

Prefer quality over blind volume.

The agent should:
1. Find vacancies.
2. Compare them against candidate_facts.md.
3. Create a PLANKA card.
4. Mark VERIFIED / ADJACENT / UNCONFIRMED / NOT MATCHED.
5. Draft a tailored cover letter.
6. Wait for Pavel's approval.
7. Submit only after approval.

## 15. Final preference rule

When two vacancies are similarly relevant, prefer the one with:
1. More creative ownership.
2. Better connection to games / narrative / Unreal / cinematic work.
3. Better compensation.
4. More interesting product.
5. Less bureaucracy.
6. Better opportunity to use Pavel's hybrid creative + technical background.

## Hard exclusions / do not search by default

### Software development vacancies

Do NOT search for or recommend roles whose primary responsibility is professional software development/programming, including:
- Software Developer
- Software Engineer
- Backend Developer
- Frontend Developer
- Fullstack Developer
- Python Developer
- JavaScript / TypeScript Developer
- Gameplay Programmer
- Engine Programmer
- Tools Programmer
- DevOps / SRE (Site Reliability Engineer) / Shift Engineer
- System Administrator / Sysadmin
- QA Engineer / Game Tester
- Mobile App Developer

Reason:
Pavel uses AI-assisted development / vibe coding for his own prototypes and tools, but does not consider himself a professional programmer.

Exception:
A technical role may still be surfaced if coding is secondary and the core role is clearly:
- AI Product / prototyping;
- creative technology;
- game/narrative tooling;
- AI workflow design;
- hybrid creative + technical work.

When uncertain, mark:
`TECHNICAL ROLE — REVIEW REQUIRED`

### GTA / SAMP / RolePlay projects

Do NOT search for or recommend vacancies primarily connected to:
- GTA SAMP
- SA-MP
- GTA RolePlay servers
- GTA RP server development/content
- FiveM roleplay projects
- similar unofficial GTA multiplayer/RP server ecosystems

These are outside Pavel's current target profile.

If a company happens to have unrelated legitimate game-development work, evaluate that role separately.
