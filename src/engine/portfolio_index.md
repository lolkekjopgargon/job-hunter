## Combat Balance and Data Architecture

https://drive.google.com/file/d/1RO46ycLAckr803ahy8ULLimjzwcHr4Bx/view?usp=drive_link

Recommended for:
- Game Designer
- Systems Designer
- Combat / Balance roles
- Data-driven / Systems-oriented Game Design roles

**Methodology demonstrated by this sample:**
`formalize system → simulate → analyze → rebalance`

This sample is **NOT** merely a collection of static balance tables or formula spreadsheets. It demonstrates Pavel's practical engineering workflow for game balance:
1. **System & rules formalization:** Defining core mechanics, variables, and interaction constraints;
2. **Data architecture:** Structuring stats, modifiers, and dependencies clearly;
3. **Automated validation & simulation:** Writing AI-assisted scripts to run large-scale automated combat simulations (including Monte Carlo testing up to massive batch sizes);
4. **Outcome analysis:** Evaluating statistical distributions, edge cases, probability skews, and dominant strategies ("имба");
5. **Rebalancing:** Adjusting rules, mechanics, and parameters based on simulated outcomes rather than manual cell-by-cell guesswork.

When citing this sample in an application for a Game Designer / Systems Designer role, frame it around this automated simulation and testing workflow.
